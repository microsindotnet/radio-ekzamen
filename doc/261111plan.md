# План реализации: тренажёр экзаменационных билетов (radio-ekzamen)

Дата: 11 ноября 2026
ТЗ: `doc/261111tz.md`
Исходный документ: `Perechen-voprosov-dlya-proverki-sootvetstviya-ekspluatatsionnoy-i-tekhnicheskoy-gotovnosti.docx`

## 1. Цель

Программа-тренажёр: показывает случайный билет (вопрос, картинку при наличии,
четыре ответа `a..d` чёрным текстом), принимает ответ пользователя `a..d`,
сообщает «Правильно»/«Ошибка», при ошибке показывает правильный ответ,
завершается по `Esc`.

## 2. Выбранный стек

- **Язык:** Python 3.13 (используется интерпретатор из pyenv, `python3` 3.13.0).
- **Разбор docx:** прямой разбор OOXML через `lxml` (5.4.0 уже установлен) +
  `zipfile`/`xml.etree`. `python-docx` **не используется** (не установлен и не
  нужен: нужен доступ к уровня ран и цвету, который удобнее получать напрямую).
- **GUI:** **PySide6** (Qt). Требуется установка: `pip install PySide6`.
  Запасной вариант без установки — `tkinter` (8.6 присутствует), если Qt поставить
  нельзя. План ориентирован на PySide6, tkinter описан как fallback (раздел 11).
- **Зависимости:** `lxml`, `PySide6`. `requirements.txt` завести в корне.

## 3. Проверенные факты о документе

Факты получены разбором `word/document.xml` (см. скрипты-разведку в истории).

1. **Билетов ровно 426**, номера 1..426, все присутствуют, дубликатов нет.
2. **У каждого билета ровно 4 ответа** `a`, `b`, `c`, `d` (ни одного билета с
   другим набором букв не найдено).
3. **Раскладка текста:** содержимое лежит внутри таблиц
   (`body > tbl > tr > tc > p`). Разбор по всем `w:p` в порядке документа
   корректно обходит таблицы.
4. **Маркеры:**
   - билет начинается абзацем `Вопрос № N`;
   - метка ответа — абзац вида `a)`/`b)`/`c)`/`d)`;
   - текст ответа — как правило следующий абзац, **но** бывают исключения:
     - в метке бывают лишние символы (напр. билет 11: абзац `a)*`);
     - иногда текст может идти в том же абзаце после метки.
     Вывод: парсер должен допускать хвост после `буква)`, а не требовать
     точного совпадения абзаца с одной буквой.
5. **Признак правильного ответа:** у правильного ответа ран(ы) имеют
   `w:rPr/w:color` со значением, отличным от чёрного. Наблюдаемые значения:
   `158466` (тёмно-бирюзовый), `FF8000`, `00A933`, `FF860D`, `FF4000`;
   чёрный — явный `000000` или `auto`.
   **Вывод: нельзя хардкодить один цвет.** Правильное правило:
   `colored := (color is not None) and color.upper() not in {"", "AUTO", "000000", "FFFFFF"}`.
   Дополнительно цвет может стоять и в свойствах метки абзаца
   (`w:pPr/w:rPr/w:color`) — учитывать как дополнительный сигнал.
6. **Правильный ответ — ровно один** в каждом из 426 билетов.
   Распределение правильной буквы: a=103, b=98, c=116, d=109 (в сумме 426).
7. **Подкраска полная:** ранее билеты **112, 164, 189, 298** были без подкраски,
   теперь исправлены, и во **всех 426** билетах ровно один подкрашенный ответ.
   Инвариант «у каждого билета ровно один `colored`» — жёсткий (см. 6 п.8).
8. **Картинки:** 37 встроенных рисунков (`w:drawing/wp:inline/.../pic/blip`),
   19 уникальных PNG в `word/media/`. Связь: `a:blip/@r:embed` → `rId` →
   `word/_rels/document.xml.rels` → `Target` (напр. `media/image1.png`).
   Картинка относится к вопросу и лежит в абзацах билета до вариантов ответа.
   Билеты с картинками (номер → файл):
   22,23→image1; 32→image2; 136→image3; 137..140→image4; 141→image5; 142→image6;
   173..176→image7; 177..180→image8; 249→image9; 263→image3; 322,323→image10;
   326..328→image11; 329→image12; 331,332→image13; 341,342→image14;
   343,344→image15; 353,354→image16; 355→image17; 406→image18; 407→image19.
   (Часть картинок переиспользуется в нескольких билетах — это нормально.)
9. Окружение: `lxml` есть, `PySide6` — нет (ставить), `tkinter` — есть.

## 5. Модель данных (`models.py`)

```python
from dataclasses import dataclass, field

@dataclass
class Answer:
    letter: str          # 'a'..'d'
    text: str            # текст ответа (может быть многострочным)
    colored: bool        # True = правильный (подкрашен)

@dataclass
class Ticket:
    number: int
    question: str
    answers: list[Answer]        # длина 4, в порядке a,b,c,d
    image_png: bytes | None = None  # сырые байты PNG, если есть

    @property
    def correct_letters(self) -> list[str]:
        return [a.letter for a in self.answers if a.colored]
```

## 6. Разбор документа (`docx_loader.py`)

Пошаговый алгоритм:

1. Открыть docx как zip. Прочитать `word/document.xml` и
   `word/_rels/document.xml.rels`. Построить карту `rId -> Target`.
2. Собрать плоский список всех `w:p` в порядке документа (`root.iter`) — это
   автоматически обходит таблицы.
3. Для каждого абзаца вычислить:
   - полный текст (`"".join(w:t)`);
   - набор `rId` картинок из `a:blip/@r:embed` (искать по **атрибуту**,
     а не по элементу: `for el in para.iter(): el.get(qr("embed"))`);
   - признак «есть цветной ран» и, при необходимости, конкретный цвет.
4. Разбить на билеты по регэкспу `^\s*Вопрос\s*№\s*(\d+)`.
5. Внутри билета:
   - абзац с меткой `^\s*([a-d])\)(.*)$` открывает новый ответ; хвост после `)`
     добавляется к тексту ответа; цвет берётся по ранам метки-абзаца;
   - последующие абзацы без метки добавляются к текущему ответу, вклад в
     `colored` — объединение по всем ранам абзаца;
   - текст вопроса — абзацы до первого ответа, исключая строку `Вопрос № N`.
6. Для каждого `rId` картинки прочитать байты из zip (`word/` + target),
   сохранить в `Ticket.image_png` (первую картинку; если их несколько — см. 10.4).
7. Определение `colored`: см. п. 5 раздела 3 (не чёрный/не auto) + фолбэк на
   `w:highlight`/цвет метки абзаца.
8. Валидация при загрузке (assert/лог): 426 билетов, у каждого 4 ответа,
   ровно один `colored`.

Ключевые тонкости (учтены явно):
- не полагаться на «метка = ровно `a)`» (есть `a)*`);
- собирать цвет по **всем** ранам варианта, а не по одному `w:r`;
- не хардкодить значение цвета;
- картинки искать по атрибуту `r:embed`, а не по элементу.

## 7. GUI (`exam.py`, PySide6)

Класс `ExamWindow(QMainWindow)`:

- Виджеты:
  - `QLabel lbl_num` — «Билет № N»;
  - `QLabel lbl_question` — текст вопроса, `setWordWrap(True)`;
  - `QLabel lbl_image` — `QPixmap` из `image_png`, масштабируется с сохранением
    пропорций (`Qt.KeepAspectRatio`), скрыт, если картинки нет;
  - 4 × `QLabel` для ответов: текст всегда **чёрным** (стиль задаём принудительно,
    исходный цвет из docx игнорируем), формат `a) текст`;
  - `QLabel lbl_result` — «Правильно» / «Ошибка: правильный ответ — <текст>».
- Ввод:
  - `QShortcut(QKeySequence("Escape"), self, self.close)` — выход (шаг 8 ТЗ);
  - `keyPressEvent`: `A..D`/`a..d` (и `Ф..В` для русской раскладки — см. 10.3)
    → проверка ответа; после показа результата любая клавиша (кроме `Esc`)
    генерирует следующий билет.
- Прокрутка: обернуть контент в `QScrollArea` — вопросы и ответы бывают длинными.

## 8. Логика тренажёра

Состояние: загруженный `list[Ticket]`, текущий билет, флаг «ответ уже дан».

1. При старте и по команде «следующий»: `num = random.randint(1, 426)`;
   взять билет с этим номером; отрисовать (шаги 1–3 ТЗ).
2. По нажатию `a..d`:
   - найти выбранный `Answer`;
   - если `answer.colored` → показать «Правильно» (шаг 6);
   - иначе → «Ошибка» и показать текст правильного ответа (шаг 7).
3. `Esc` в любой момент → выход из приложения.

## 9. Запуск и зависимости

- `requirements.txt`: `lxml>=5`, `PySide6`.
- Установка: `python3 -m pip install -r requirements.txt`.

## 10. Краевые случаи и принятые решения

### 10.1. Билеты без подкрашенного ответа
После исправления документа таких билетов нет: во всех 426 билетах ровно один
подкрашенный ответ. Защитный код на будущее оставить: если при загрузке найден
билет без единого `colored`, залогировать предупреждение и не выдавать его в
экзамене автоматически (перегенерировать номер). Угадывать правильный ответ
не нужно.

### 10.2. Случайный номер
При выпадении номера билета, не прошедшего валидацию (10.1), номер
перегенерируется (кроме режима `--num`).

### 10.3. Раскладка клавиатуры
Пользователь может быть в русской раскладке: обрабатывать и латинские `a..d`,
и кириллические `ф..в` (ф→a, ы→s, в→d, но для наших букв: a=ф, b=и, c=с, d=в —
уточнить сопоставление и покрыть тестом).

### 10.4. Несколько картинок в билете
В данных у каждого билета максимум одна картинка, поэтому берём первую.
Заложить в модель возможность списка на будущее (не усложняя сейчас).

### 10.5. Длинные ответы
Вопросы/ответы бывают длинными → `QScrollArea` + wordwrap (см. раздел 7).

## 11. Fallback без Qt (tkinter)

Если PySide6 установить нельзя: `tkinter` + `Pillow` (для PNG; проверить наличие).
Логика та же, отличается только слой представления. Выделить интерфейс
`render(ticket)` / `read_answer()`, чтобы смена GUI не затрагивала ядро.
Pillow сейчас не проверялся — уточнить перед выбором fallback.

## 12. Тестирование

- **Загрузчик (`tests/test_docx_loader.py`):**
  - ровно 426 билетов, номера 1..426 без пропусков;
  - у каждого 4 ответа `a..d`;
  - у всех 426 билетов ровно один `colored` (без исключений);
  - контрольные билеты: №1 → правильный `d`; №11 → правильный `a` (и текст
    начинается с `*RA3A`); №112 → правильный `a`; №189 → правильный `d`;
    №22 → есть картинка `image1.png`.
  - корректность привязки картинок: 37 билетов с картинкой, набор совпадает
    с перечнем из раздела 3 п.8.
- **Логика экзамена:** юнит-тест функции проверки ответа (colored → правильно,
  не colored → ошибка + правильный текст).
- **Ручная проверка GUI:** запуск, `Esc`, русская раскладка, билет с картинкой.

## 13. Риски и открытые вопросы

1. **Поведение после ответа:** ТЗ не описывает переход к следующему билету.
   Предложение: после показа результата следующая клавиша (кроме `Esc`) выдаёт
   новый билет. Уточнить.
2. **Чем считать «подкрашенный»:** принято «любой не чёрный/не auto цвет»;
   если появятся тематические заголовки с цветом внутри билетов — правило
   сохраняется, т.к. рассматриваются только раны ответов.
3. **Версия документа:** карта картинок и распределение ответов привязаны к
   текущему файлу; при обновлении docx — перепроверить (тест-снимок поможет).
4. **PySide6 на целевой ОС** — уточнить платформу запуска (Windows/Linux) для
   упаковки; при необходимости предусмотреть PyInstaller.

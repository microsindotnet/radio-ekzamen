# Тренажёр экзаменационных билетов на получение радиолюбительской категории

## 1. Назначение программы

Программа предназначена для подготовки к экзамену по эксплуатационной и
технической готовности. Она показывает экзаменационные билеты (всего 426,
исходный документ [1]), перемешивает варианты ответов и проверяет выбранный
ответ.

Каждый билет содержит:

- номер;
- текст вопроса;
- четыре варианта ответа (в исходном документе [1] — `a`, `b`, `c`, `d`);
- необязательную растровую картинку, связанную с вопросом.

Программа правильный ответ по данным из `src/answers.py` и показывает
пользователю варианты.

Дополнительно программа ведёт статистику ошибочных ответов в файле
`err_stat.txt` и периодически предлагает билеты, в которых пользователь уже
ошибался, чтобы плохо усвоенные вопросы повторялись чаще.

## 2. Как использовать

### Требования

- Python 3.10 или новее.
- Tkinter (входит в стандартную поставку Python) — для показа картинок.
  Если Tkinter недоступен, текст билета всё равно выводится, а картинка
  не открывается.

Сторонние библиотеки для запуска не нужны: данные уже подготовлены в
`src/tickets.py` и `src/answers.py`, картинки лежат в `src/media/`.

### Запуск

Из каталога проекта:

```bash
python3 main.py -h          # подсказка
python3 main.py -n=22       # показать билет № 22
python3 main.py -r          # показать случайный билет
python3 main.py -t          # тест: случайные билеты до нажатия Esc
python3 main.py -t -e       # тест, сложные билеты в 2 раза чаще
```

Запуск без опций равносилен `-h`.

### Опции

| Опция | Значение |
|---|---|
| `-n N`, `--num N` | Показать билет с номером `N` (1..426) и завершиться после ответа. |
| `-r`, `--random` | Показать один случайный билет и завершиться после ответа. |
| `-t`, `--test` | Тест: показывать случайные билеты подряд, пока не нажат `Esc`. В конце выводится статистика. |
| `-e`, `--extend` | Модификатор: сложные билеты (`hard`) предлагаются в 2 раза чаще, а их заголовок выводится жёлтым цветом. |
| `-h`, `--help` | Подсказка по командной строке. |

Опции `-n`, `-r` и `-t` взаимно исключающие. `-e` можно добавлять к `-r` и `-t`
(и к `-n`, но на конкретный номер она не влияет, кроме цвета заголовка).

### Управление

- `1`, `2`, `3`, `4` — выбрать вариант ответа.
- `Esc` — завершить программу (в режиме `-t` — завершить тест и показать
  статистику).

### Результат ответа

- Правильный ответ — зелёное сообщение `Правильно`.
- Неправильный ответ — красное сообщение `Ошибка` и правильный вариант.

## 3. Алгоритм работы в разных режимах

### 3.1. Показ билета (общая часть)

1. Печатается разделитель `----------------------------`.
2. Печатается заголовок `Билет № N` (в режиме `-e` для сложного билета —
   жёлтым).
3. Печатается текст вопроса.
4. Если у билета есть картинка, она открывается в отдельном окне
   (`src/picview.py`, Tkinter) слева по горизонтали и по центру по вертикали.
   Окно не забирает фокус у консоли и закрывается после нажатия клавиши.
5. Четыре варианта ответа перемешиваются случайным образом и печатаются
   с номерами `1..4`.
6. Программа ждёт нажатия `1..4` или `Esc`.

Правильный вариант определяется по букве из `src/answers.py`.

### 3.2. Режим `-n N` (`--num`)

Показывает ровно один указанный билет, ждёт ответ, обновляет `err_stat.txt`
и завершается. Номер проверяется на диапазон 1..426; иначе выводится ошибка.

### 3.3. Режим `-r` (`--random`)

Выбирает один случайный билет, показывает его, ждёт ответ, обновляет
`err_stat.txt` и завершается. Случайный выбор учитывает тренировочный счётчик
(см. 3.6), но при одном билете всегда выдаётся обычный случайный билет.

### 3.4. Режим `-t` (`--test`)

Бесконечный тест:

1. Выбирается следующий билет (с учётом тренировочного счётчика и без
   повтора последних 10 билетов).
2. Билет показывается, пользователь отвечает.
3. Обновляется `err_stat.txt`.
4. Цикл повторяется, пока не нажат `Esc`.
5. После `Esc` печатается статистика в рамке:

```
+----------------------+
| Пройдено вопросов: N |
| Из них верно: Y      |
| Ошибок: Z            |
+----------------------+
```

`Y` выводится зелёным, `Z` — красным.

### 3.5. Опция `-e` (`--extend`)

Модифицирует случайный выбор:

- каждый сложный билет (`hard=True`) получает вес 2, простой — вес 1;
- заголовок сложного билета печатается жёлтым цветом.

Сложным считается билет, у которого hard в массиве tickets.py был true.
Какой билет сложный, я выбирал сам, подкрашивая ответ в документе [1]
оранжевым цветом. Из 426 билетов сложных 149, простых 277.

### 3.6. Тренировочный счётчик (повтор ошибочных билетов)

При выдаче случайного билета (`-r`, `-t`) работает счётчик `training`, а
также окно последних показанных билетов `recent` (не длиннее 10). Обычный
случайный билет НИКОГДА не берётся из `recent` и из списка ошибочных, поэтому
недавние билеты не повторяются, а ошибочные показываются только счётчиком;
сложные билеты (`hard`) выпадают в 2 раза чаще.

1. Изначально `training = 0`, `recent` пуст.
2. Если `training == 0` и в `err_stat.txt` есть строки, задаётся
   `training = 10 + G`, где `G = random(5..10)` (далее действует пункт 3).
   То есть ошибочный билет повторяется не раньше, чем через `10 + G` вопросов.
3. Пока `training > 1`, выдаётся обычный случайный билет (не из `recent` и
   не ошибочный), а `training` уменьшается на 1.
4. Когда `training == 1`, выбирается случайный билет из списка ошибочных
   (`err_stat.txt`). Если он не входит в `recent`, он показывается, а
   `training` сбрасывается в 0. Если входит — показывается обычный случайный
   билет, а `training` при этом НЕ уменьшается, чтобы повторить попытку при
   следующем выборе.

Каждый показанный билет добавляется в `recent`; при переполнении самый старый
вытесняется. В результате билеты, в которых пользователь уже ошибался,
предлагаются отдельно от произвольных и повторяются строго не раньше, чем
через `10 + G` вопросов (`G = 5..10`) — их выдаёт только счётчик, случайный
выбор их не берёт.

### 3.7. Файл `err_stat.txt`

Лежит рядом с `main.py`. Хранит статистику ошибок по билетам. Формат строки:

```
NNN ошибок K
```

где `NNN` — номер билета, дополненный нулями слева до 3 знаков, `K` — число
ошибок. Строки всегда отсортированы по номеру билета.

Обновление после каждого ответа:

| Событие | Действие |
|---|---|
| Ошибка, строки нет | добавить `NNN ошибок 1` |
| Ошибка, строка есть | увеличить `K` на 1 |
| Правильный ответ, `K > 1` | уменьшить `K` на 1 |
| Правильный ответ, `K == 1` | удалить строку |
| Нажат `Esc` | файл не меняется |

Пример:

```
005 ошибок 1
023 ошибок 2
100 ошибок 1
```

## 4. Структура проекта

```
main.py            — точка входа, разбор опций, показ билетов, статистика
src/
  tickets.py       — 426 билетов (номер, вопрос, 4 ответа, картинка, hard)
  answers.py       — правильные ответы (номер билета → буква a..d)
  stat.py          — работа с err_stat.txt
  picview.py       — отдельный просмотрщик картинок (Tkinter)
  media/           — картинки picNNN.png
err_stat.txt       — статистика ошибок (создаётся при первом запуске)
```

## 6. Онлайн-версия на Vue

Онлайн-версия тренажёра находится в каталоге `Vue/` и написана на TypeScript
(Vue 3 + Vite). Она полностью работает в браузере, сервер не нужен.

При открытии страницы сразу запускается тест (аналог
`python3 main.py -t -e`):

- варианты ответов перемешиваются и нумеруются `1..4`; ответ — клавиши
  `1`..`4`, `Esc` завершает тест и выводит итог в рамке;
- сложные билеты (`hard`) предлагаются в 2 раза чаще, их заголовок жёлтый;
- ошибочные билеты показываются не раньше, чем через `10 + G` вопросов
  (`G = 5..10`) — см. раздел 3.6;
- текущая статистика ошибок выводится внизу на отдельной плашке.

Отличия от консольной версии: картинка билета показывается прямо на
странице, а статистика ошибок (аналог `err_stat.txt`) хранится в браузере в
`localStorage`; при первом открытии в неё переносится содержимое
`Vue/src/errStat.ts`.

Структура `Vue/`:

```
index.html               — HTML-страница приложения
src/
  main.ts                — точка входа
  App.vue                — шапка, консоль и плашка статистики
  tickets.ts             — 426 билетов (аналог src/tickets.py)
  answers.ts             — правильные ответы (аналог src/answers.py)
  errStat.ts             — начальное содержимое err_stat.txt
  training-algorithm.ts  — статистика ошибок и выбор билета
  composables/useExam.ts — ход теста (вывод, клавиши)
  components/            — консоль и плашка статуса
  core/types.ts          — типы
public/media/            — картинки билетов picNNN.png
```

### 6.1. Как компилировать

Нужен Node.js 18 или новее.

```bash
cd Vue
npm install        # установить зависимости
npm run dev        # режим разработки, http://localhost:5173
npm run typecheck  # проверка типов (vue-tsc)
npm run build      # сборка в Vue/dist
npm run preview    # локальный просмотр собранной версии
```

### 6.2. Как публиковать на веб-сайте

Сборка полностью статическая (только HTML/CSS/JS), сервер не требуется.

1. Соберите проект:
   ```bash
   cd Vue
   npm install
   npm run build
   ```
   Появится каталог `Vue/dist`.
2. Скопируйте всё содержимое `Vue/dist` в каталог, отдаваемый веб-сервером,
   например:
   ```bash
   scp -r Vue/dist/* user@example.org:/var/www/html/
   ```

В `vite.config.ts` задано `base: './'`, поэтому сборку можно размещать и в
корне сайта, и в подкаталоге (например, `https://example.org/radio/`) без
каких-либо правок.

Примеры размещения:

- статический хостинг (GitHub Pages, Netlify, Cloudflare Pages): каталог
  публикации — `Vue/dist`;
- nginx: положите файлы в `root`; для `/` достаточно отдавать `index.html`
  (приложение без маршрутизации);
- обновление версии — снова скопировать содержимое `dist`.
